# stirkabot-core

Ядро СтиркаБота — бота ВКонтакте для записи на стиральные машины в общежитии. Здесь только правила: на какие слоты делится день и кто может записаться.

## Как запустить локально

```
python -m venv .venv
.venv/Scripts/activate        # Linux/macOS: source .venv/bin/activate
pip install -r requirements-dev.txt
pytest --cov
```

## CI/CD: стадии пайплайна

Пайплайн описан в [.gitlab-ci.yml](.gitlab-ci.yml) и запускается **только** для Merge Request и для ветки `main`. На тегах пайплайн не запускается.

| Стадия | Job | Что делает | Зачем | Если упал |
|---|---|---|---|---|
| build | `build:wheel` | Собирает wheel, ставит его и импортирует пакет | Убедиться, что проект вообще собирается, и передать собранный файл дальше | Пайплайн красный |
| lint | `lint:ruff` | Стиль и типичные ошибки (ruff), отчёт Code Quality | Единый стиль, ошибки видно прямо в MR | ⚠ Жёлтый значок, тесты всё равно идут |
| lint | `lint:mypy` | Строгая проверка типов (эксперимент) | Пробуем ввести типизацию без риска остановить работу | ⚠ Только предупреждение |
| test | `test:pytest` | Тесты, отчёт JUnit и покрытие (cobertura) | Проверить правила записи; результаты тестов и покрытие видно во вкладке MR | Пайплайн красный, MR нельзя слить |
| test | `test:python-3.13` | Те же тесты на Python 3.13 (эксперимент) | Заранее узнать о проблемах при переходе на новый Python | ⚠ Только предупреждение |
| package | `package:release-archive` | Архив `stirkabot-core-<версия>.tar.gz`: wheel, README, контрольные суммы | Готовый к выкладке артефакт | Пайплайн красный |

**Порядок:** `lint:*` и `test:python-3.13` ничего не ждут (`needs: []`) и идут сразу. `test:pytest` ждёт только `build:wheel`, поэтому падение линтера не останавливает тесты. `package` запускается только после успешных сборки и тестов.

**Кэш:** папка `.cache/pip`, ключ — содержимое `requirements-dev.txt`. Зависимости не скачиваются заново, пока файл не изменился.

**Артефакты:**
- `dist/*.whl` — собранный пакет (неделю);
- `report.xml` и `coverage.xml` — отчёт тестов и покрытия (неделю), GitLab показывает их во вкладке Tests и прямо в diff MR;
- `gl-code-quality-report.json` — замечания линтера;
- `stirkabot-core-*.tar.gz` — архив для выкладки (30 дней).

## Как работает команда

- Прямой push в `main` запрещён (protected branch), всё через Merge Request и минимум один approve.
- Ветки: `feature/<номер issue>-<коротко>`.
- Коммиты: Conventional Commits (`feat:`, `fix:`, `ci:`, `test:`, `docs:`, `style:`).

| Участник | Отвечает за |
|---|---|
| A | Стадии build и lint |
| B | Стадия test и отчёты о покрытии |
| C | Артефакты, кэш, правила запуска, стадия package |
